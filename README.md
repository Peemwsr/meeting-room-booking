# ระบบจองห้องประชุมจังหวัดสกลนคร (ผู้จองไม่ต้องล็อกอิน)

เว็บจองห้องประชุมแบบเดียวกับ Google Form เดิม คือ **ผู้จองกรอกข้อมูลแล้วจองได้เลย ไม่ต้องสมัครสมาชิก** แต่ดีกว่าเดิมตรงที่ผู้จอง **ยกเลิกหรือแก้ไขการจองเองได้** ด้วย "รหัสการจอง" ที่ระบบออกให้ตอนจอง ส่วนผู้ดูแลล็อกอินเพื่อจัดการห้องและดูข้อมูลผู้จอง ใช้ [Supabase](https://supabase.com) เป็นฐานข้อมูล หน้าเว็บเป็นไฟล์นิ่ง และมีตัวส่งอีเมลเล็ก ๆ (`mailer.js`) ส่งอีเมลยืนยันผ่าน SMTP ฟรี

```
room-booking-supabase/
├─ supabase/schema.sql     ← สคริปต์ฐานข้อมูล (รันครั้งเดียวใน Supabase)   reset.sql = ล้างของเดิม (ใช้ตอนทดลอง)
├─ web/                    ← หน้าเว็บทั้งหมด (index.html, app.js, style.css, config.js, assets/)
│   └─ config.js           ← ใส่ URL และคีย์ anon ของ Supabase ที่นี่
├─ server.js               ← เว็บเซิร์ฟเวอร์ไฟล์นิ่ง + ตัวส่งอีเมล (รันด้วย node server.js)
├─ mailer.js               ← ตัวส่งอีเมล (รันเดี่ยวได้ด้วย node mailer.js)
├─ .env.example            ← ตัวอย่างไฟล์ตั้งค่าฝั่งเซิร์ฟเวอร์ (คัดลอกเป็น .env)
└─ tests/                  ← ชุดทดสอบ (ไม่บังคับ)
```

## วิธีที่ผู้จองใช้
1. เปิดเว็บ เลือกห้อง วัน และช่วงเวลาบนปฏิทิน (ปุ่ม เช้า / บ่าย / เต็มวัน หรือเลือกรายชั่วโมง) กรอกข้อมูลตามแบบฟอร์มเดิม ติ๊กยอมรับการเก็บข้อมูล แล้วกดจอง
2. ระบบแสดง **รหัสการจอง** และลิงก์ยกเลิก/แก้ไข (และส่งอีเมลยืนยันพร้อมลิงก์เดียวกัน ถ้าเปิดการส่งอีเมลไว้)
3. ยกเลิกหรือแก้ไขภายหลังได้ 4 ทาง: กดลิงก์ในอีเมล · เมนู **การจองของฉัน** บนเครื่องที่ใช้จอง (เครื่องจำรหัสไว้ให้) · วางรหัสในช่อง "มีรหัสการจอง?" · กรอกอีเมลในช่อง "ลืมรหัส?" เพื่อให้ส่งลิงก์ใหม่ (ออกรหัสใหม่ รหัสเดิมจะใช้ไม่ได้)
4. ถ้ารหัสหายหมด ผู้ดูแลยกเลิกให้ได้

คนทั่วไปเห็นปฏิทินเป็นช่วงที่ "ไม่ว่าง" เท่านั้น **ไม่เห็นชื่อ หัวข้อ เบอร์ หรืออีเมลของใคร** ผู้จองเห็นรายละเอียดเฉพาะการจองของตัวเอง

## ผู้ดูแลทำอะไรได้
ล็อกอินที่ปุ่ม "สำหรับผู้ดูแล" มุมบนขวา: ดูปฏิทินแบบเห็นรายละเอียดทุกการจอง · หน้า **งานผู้ดูแล** (เบอร์/อีเมลผู้จอง ความต้องการ ติ๊กเตรียมห้อง) · จองแทนผู้อื่น แก้ไข ยกเลิกพร้อมเหตุผล (ผู้จองได้รับอีเมลแจ้ง) · **จัดการห้อง** (เพิ่ม แก้ไข ปิด ลบ รูป) และตัวเลือกอุปกรณ์/ความต้องการ · **ตั้งค่าอีเมล** · กระดิ่งแจ้งเตือนเมื่อผู้จองจอง/แก้ไข/ยกเลิก · ตั้งสิทธิ์ผู้ดูแลให้บัญชีอื่น

## ขั้นตอนติดตั้ง (ประมาณ 30–40 นาที)

### 1) สร้างโปรเจกต์ Supabase และฐานข้อมูล
1. สมัคร https://supabase.com → **New project** เลือกภูมิภาคใกล้ไทย (เช่น Singapore) ตั้งรหัสผ่านฐานข้อมูลแล้วเก็บไว้
2. **SQL Editor → New query** วางไฟล์ `supabase/schema.sql` ทั้งไฟล์ กด **Run** (รันซ้ำได้) ถ้าเคยรันเวอร์ชันที่ต้องล็อกอินไว้ ให้รัน `supabase/reset.sql` ก่อน (ข้อมูลการจองเดิมจะหาย)

### 2) ตั้งค่าบัญชีผู้ดูแล
1. **Authentication → Sign In / Providers (หรือ Providers → Email):** เปิด Email แต่ **ปิด "Allow new users to sign up"** เพราะผู้จองไม่ต้องมีบัญชี ถ้าเปิดไว้ คนนอกจะสมัครบัญชีเองได้ (แม้ไม่มีสิทธิ์อะไรก็ตาม)
2. **Authentication → Users → Add user:** สร้างบัญชีผู้ดูแล (อีเมลและรหัสผ่าน ติ๊ก Auto Confirm) แล้วรันใน SQL Editor (แก้อีเมล)
   ```sql
   update public.profiles set role = 'admin' where email = 'อีเมลผู้ดูแล';
   ```
   ผู้ดูแลคนอื่นเพิ่มภายหลังได้โดยสร้างบัญชีแบบเดียวกัน แล้วตั้งสิทธิ์ที่เมนู **บัญชีผู้ดูแล** ในเว็บ
3. **Authentication → URL Configuration:** ใส่ *Site URL* และ *Redirect URLs* เป็นที่อยู่เว็บของคุณ (ใช้กับลิงก์ลืมรหัสผ่านของผู้ดูแล)

### 3) ใส่คีย์ในหน้าเว็บ
**Project Settings → API** คัดลอก **Project URL** กับคีย์ **anon public** (ในหน้าจอรุ่นใหม่เรียก *publishable key*) ไปใส่ใน `web/config.js`
คีย์นี้ใส่ในหน้าเว็บได้ เพราะความปลอดภัยอยู่ที่กติกาในฐานข้อมูล **ห้ามใส่ `service_role` / secret key ในโฟลเดอร์ web/ เด็ดขาด** (คีย์นั้นใช้เฉพาะบนเซิร์ฟเวอร์ในข้อ 5)

### 4) เปิดเว็บ
```bash
npm install          # ติดตั้ง nodemailer (ใช้เฉพาะตัวส่งอีเมล)
node server.js       # เปิดที่ http://localhost:8080
```
หรือจะฝากโฟลเดอร์ `web/` ไว้บริการไฟล์นิ่ง (Cloudflare Pages / Netlify / GitHub Pages) หรือ Nginx/Caddy ก็ได้ (ดูหัวข้อ "ขึ้นโดเมนจริง") แต่ถ้าต้องการส่งอีเมล ต้องมีเครื่องที่เปิดตลอดรัน `node mailer.js` (ข้อ 5)

### 5) เปิดการส่งอีเมลด้วย SMTP ฟรี
ระบบส่งอีเมล: ยืนยันการจอง (พร้อมรหัสและลิงก์) · ยืนยันการยกเลิก · แจ้งผู้จองเมื่อผู้ดูแลแก้ไข/ยกเลิก · แจ้งผู้ดูแลเมื่อมีการจอง/แก้ไข/ยกเลิก · ลิงก์ใหม่เมื่อผู้จองลืมรหัส
1. สมัครบริการ SMTP ฟรี ตัวอย่างที่ตรวจแล้วขณะเขียนคือ **Brevo** (ฟรี 300 ฉบับ/วัน ใช้ SMTP ได้ ต้องรอ Brevo อนุมัติบัญชีก่อนจึงส่งได้) ตั้งค่าตามเอกสารของผู้ให้บริการ: เซิร์ฟเวอร์ `smtp-relay.brevo.com` พอร์ต `587` ชื่อผู้ใช้เป็นอีเมลที่ล็อกอิน รหัสผ่านเป็น *SMTP key* และต้องยืนยันที่อยู่ผู้ส่งไว้ก่อน บริการอื่น เช่น Gmail (ใช้ App Password) ก็ใช้ได้ ให้ตรวจโควตาและเงื่อนไขล่าสุดกับผู้ให้บริการเอง
2. คัดลอก `.env.example` เป็น `.env` แล้วกรอก `SUPABASE_URL`, `SUPABASE_SERVICE_ROLE_KEY` (คีย์ลับจาก Project Settings → API) และค่า `SMTP_*` (ไฟล์ `.env` ห้ามนำขึ้นที่เก็บโค้ดสาธารณะ ตั้งไว้ใน `.gitignore` แล้ว)
3. รัน `node server.js` (เปิดเว็บและตัวส่งอีเมลพร้อมกัน) หรือ `node mailer.js` (เฉพาะตัวส่งอีเมล) ต้องเห็นข้อความ `[mailer] เริ่มทำงาน`
4. ในเว็บ ล็อกอินผู้ดูแล → **จัดการห้อง → การส่งอีเมล** ใส่ "ที่อยู่เว็บ" (เช่น `https://rooms.ชื่อโดเมน.go.th`) และอีเมลผู้ดูแลที่จะรับแจ้ง กดบันทึก **ถ้าเว้นที่อยู่เว็บไว้ ระบบจะไม่ส่งอีเมลเลย** ตรงนี้ยังบอกสถานะคิว (รอส่ง/ส่งแล้ว/ไม่สำเร็จ) ให้ด้วย
5. ทดลองจองด้วยอีเมลของคุณ ควรได้อีเมลภายในไม่กี่วินาที ถ้าอีเมลค้างในคิว ดูข้อความผิดพลาดที่หน้าจอของ `node server.js`

อีเมลที่ส่งไม่สำเร็จจะลองใหม่ให้อัตโนมัติสูงสุด 5 ครั้ง หลังส่งแล้ว (หรือเลิกลอง) ระบบล้างเนื้อหาอีเมลที่มีรหัสการจองออกจากคิวทันที

## ขึ้นโดเมนจริง
- ขอโดเมนย่อยของโดเมนหน่วยงานจากผู้ดูแลเว็บหลัก ให้ชี้มาที่เซิร์ฟเวอร์ (หรือ CNAME ไปที่บริการฝากไฟล์นิ่ง) ต้องเป็น **HTTPS**
- ตัวอย่าง Caddy (ได้ใบรับรองอัตโนมัติ):
  ```
  rooms.ชื่อโดเมน.go.th {
    root * /path/to/room-booking-supabase/web
    file_server
  }
  ```
  แล้วรัน `node mailer.js` แยกไว้ (เช่นด้วย pm2 หรือ systemd) หรือใช้ `node server.js` อยู่หลัง Caddy ก็ได้
- ใส่ที่อยู่เว็บเดียวกันใน Supabase (ข้อ 2.3) และในหน้า "การส่งอีเมล" (ข้อ 5.4) จากเว็บหลักของหน่วยงานให้วางปุ่มหรือลิงก์เปิดหน้าใหม่ (ไม่ฝัง iframe)

## ขึ้น GitHub ก่อน (เก็บโค้ด + ฝากเว็บชั่วคราวบน GitHub Pages)
1. สร้าง repository ว่างบน github.com จะเลือก Public หรือ Private ก็ได้
2. ในโฟลเดอร์โปรเจกต์ รัน (แก้ชื่อผู้ใช้และชื่อ repo):
   ```bash
   git init && git add . && git commit -m "ระบบจองห้องประชุม"
   git branch -M main
   git remote add origin https://github.com/ชื่อผู้ใช้/ชื่อ-repo.git
   git push -u origin main
   ```
   ก่อน commit ให้รัน `git status` ตรวจว่า **ไม่มีไฟล์ `.env`** อยู่ในรายการ (`.gitignore` กันไว้ให้แล้ว) ถ้าเผลอ commit คีย์ `service_role` ขึ้นไป ให้เปลี่ยนคีย์ใน Supabase ทันที เพราะประวัติใน git ยังเก็บคีย์เดิมไว้
3. **Settings → Pages → Source = GitHub Actions** ไฟล์ `.github/workflows/pages.yml` จะเผยแพร่โฟลเดอร์ `web/` ให้ทุกครั้งที่ push (ดูผลที่แท็บ Actions) ที่อยู่เว็บจะเป็น `https://ชื่อผู้ใช้.github.io/ชื่อ-repo/`
4. นำที่อยู่นั้นไปใส่ใน Supabase (Authentication → URL Configuration) และในหน้าผู้ดูแล "การส่งอีเมล" (ไม่ต้องมี `/` ท้าย) ตัวหน้าเว็บใช้เส้นทางแบบสัมพัทธ์ จึงทำงานใต้ `/ชื่อ-repo/` ได้
5. **GitHub Pages ไม่รันโปรแกรมให้** ตัวส่งอีเมลจึงต้องรัน `node mailer.js` บนเครื่องอื่นที่เปิดตลอด ถ้ายังไม่มี ระบบก็ยังจองและยกเลิกด้วยรหัสได้ตามปกติ เพียงไม่มีอีเมล
6. สิ่งที่จะเห็นสาธารณะถ้าตั้ง repo เป็น Public: โค้ด, `web/config.js` (URL และคีย์ anon ซึ่งออกแบบให้เปิดเผยได้ ใครเปิดเว็บก็เห็นอยู่แล้ว), ตราจังหวัด และชื่อห้องที่ใส่ในโค้ด ไม่มีข้อมูลผู้จองอยู่ใน repo ถ้าไม่ต้องการเปิดเผย ให้ตั้งเป็น Private แต่ GitHub Pages ของ repo ส่วนตัวอาจต้องใช้แพ็กเกจแบบชำระเงิน ให้ตรวจเงื่อนไขล่าสุดของ GitHub ก่อน
7. ไฟล์ workflow ใช้ Actions เวอร์ชันหลักที่ใช้กันอยู่ขณะเขียน (`checkout@v4`, `upload-pages-artifact@v3`, `deploy-pages@v4`) ผมยังไม่ได้รันบน GitHub จริง ถ้า Actions แจ้งเตือนว่าเวอร์ชันเก่า ให้ขยับเลขเวอร์ชันตามที่ GitHub แนะนำ

## ที่ผู้ใช้ต้องรู้เรื่องความเสี่ยง (ควรอ่านก่อนเปิดจริง)
- **ใครก็จองในนามใครก็ได้** เพราะไม่มีบัญชีให้ตรวจสอบ ระบบป้องกันด้วย: จำกัดจำนวนการจองต่อชั่วโมง (ต่อ IP, ต่อทั้งระบบ, และจำนวนการจองที่ยังไม่ถึงวันต่ออีเมล) · ช่องดักบอตที่ซ่อนอยู่ · ผู้ดูแลยกเลิกการจองใด ๆ ได้ทันที ค่าจำกัดแก้ได้ที่ตาราง `settings` (`limit_ip_per_hour`, `limit_global_per_hour`, `limit_active_per_email`) ตัวเลขเริ่มต้นเป็นเพียงข้อเสนอ
- **ยังไม่มี CAPTCHA** เพราะการตรวจ CAPTCHA ต้องมีโค้ดฝั่งเซิร์ฟเวอร์ (เพิ่มภายหลังได้ เช่น Cloudflare Turnstile ผ่าน Supabase Edge Function) ถ้าเจอการจองปั่น ให้ลดค่าจำกัดใน `settings` ก่อน
- **IP ที่ฐานข้อมูลเห็นอาจไม่ใช่ IP จริงของผู้จอง** ในบางสภาพแวดล้อม (ตรวจจาก header ของ Supabase) ตัวจำกัดรวมทั้งระบบเป็นตัวกันสำรอง
- **ผู้ที่มีรหัสหรือลิงก์การจองยกเลิก/แก้ไขได้และเห็นเบอร์/อีเมลของการจองนั้น** จึงควรเตือนผู้จองไม่ให้แชร์ลิงก์ (มีข้อความเตือนในหน้าจอแล้ว) รหัสสุ่ม 122 บิต เดาไม่ได้ และฐานข้อมูลเก็บเฉพาะค่าเข้ารหัสทางเดียว (sha256)
- **การขอลิงก์ใหม่ทางอีเมลทำให้รหัสเดิมใช้ไม่ได้** ระบบจำกัดไม่เกิน 3 ครั้งต่อชั่วโมงต่ออีเมล และไม่เปิดเผยว่าอีเมลนั้นมีการจองหรือไม่
- **PDPA:** แก้ข้อความยอมรับการเก็บข้อมูลในหน้าจอจอง (ค้นคำว่า `ข้าพเจ้ายอมรับ` ใน `web/app.js`) ให้ตรงกับประกาศความเป็นส่วนตัวฉบับจริง และกำหนดระยะเก็บข้อมูล ระบบยังไม่มีงานลบอัตโนมัติ ตัวอย่างลบเบอร์/อีเมลของการจองเก่าด้วยมือ:
  ```sql
  delete from public.booking_contacts c using public.bookings b where b.id = c.booking_id and b.day < current_date - interval '12 months';
  ```
  (12 เดือนเป็นเพียงตัวอย่าง) และควรล้างตาราง `rate_events` / `email_outbox` ที่เก่าเป็นรอบ ๆ ด้วย

| งาน | ทำอย่างไร |
|---|---|
| เพิ่มห้อง / ปิดห้อง / รูปห้อง | เมนู **จัดการห้อง** (ห้องที่เคยมีการจองแล้วลบไม่ได้ ให้ปิดใช้งานแทน) |
| เพิ่มผู้ดูแล | สร้างบัญชีที่ Supabase → Authentication → Users แล้วตั้งสิทธิ์ที่เมนู **บัญชีผู้ดูแล** |
| เปลี่ยนเวลาเปิดจอง | SQL: `update public.settings set value='480' where key='day_start_min';` และ `day_end_min` (นาทีนับจากเที่ยงคืน 960 = 16:00) แล้วแก้ `DAY_START_HOUR` / `DAY_END_HOUR` ใน `web/config.js` ให้ตรงกัน |
| เปลี่ยนความหมายปุ่มเช้า/บ่าย/เต็มวัน | แก้ `PRESETS` ใน `web/app.js` (ค่าเริ่มต้น เช้า 08–12, บ่าย 13–16, เต็มวัน 08–16) |
| ย้ายคนที่รหัสหาย | ผู้ดูแลแก้ไข/ยกเลิกให้ในเมนูปฏิทินหรืองานผู้ดูแล ผู้จองจะได้อีเมลแจ้ง |

## ถ้ามีปัญหา
| อาการ | สาเหตุที่พบบ่อย |
|---|---|
| หน้าเว็บขึ้น "ยังไม่ได้ตั้งค่า Supabase" | ยังไม่ได้ใส่ URL/คีย์ใน `web/config.js` |
| ผู้ดูแลล็อกอินแล้วขึ้น "ไม่ได้รับสิทธิ์ผู้ดูแล" | ยังไม่ได้รัน SQL ตั้ง role เป็น admin หรือพิมพ์อีเมลไม่ตรง |
| จองแล้วขึ้น "ทำรายการถี่เกินไป" | ชนตัวจำกัดจำนวนครั้ง (ผู้ใช้หลายคนที่อยู่หลังเครือข่ายเดียวกันอาจใช้ IP เดียวกัน) ปรับ `limit_ip_per_hour` ใน `settings` |
| ไม่มีอีเมลออก | ยังไม่ได้ใส่ "ที่อยู่เว็บ" ในหน้าการส่งอีเมล · ไม่ได้รัน `mailer.js` · ค่า SMTP ผิด (ดูข้อความที่หน้าจอ mailer) · บัญชี SMTP ยังไม่ได้รับอนุมัติ |
| คนอื่นจองแล้วปฏิทินไม่ขยับทันที | ปฏิทินสาธารณะอัปเดตผ่านเรียลไทม์ (ตาราง `public_slots`) และรีเฟรชเองทุก 60 วินาทีกับเมื่อกลับมาที่แท็บ ตรวจที่ Database → Publications ว่ามี `public_slots` |
| รูปห้องไม่ขึ้น | ตรวจ Storage มี bucket `room-photos` และบัญชีที่อัปโหลดเป็นผู้ดูแล |

## การทดสอบที่ทำแล้ว (และที่ยังไม่ได้ทำ)
- ฐานข้อมูล: 65 ข้อบน PostgreSQL 16 จริง (สิทธิ์ของคนไม่ล็อกอิน, การจองซ้อน, การจอง 20 คำขอพร้อมกัน, รหัสการจอง, ตัวจำกัดอัตรา, คิวอีเมล) → `tests/test_sql.py`
- ตัวส่งอีเมล: 8 ข้อ กับ REST และ SMTP จำลอง (ส่งไม่ซ้ำแม้เปิดสองตัว, ลองใหม่, ล้างรหัสออกจากคิว) → `tests/mailer_test.js`
- หน้าเว็บ: 51 ข้อกับตัวจำลอง Supabase → `tests/web/` (ต้อง `npm i -D jsdom` ก่อนรัน)
- **ยังไม่ได้ทดสอบ:** กับโปรเจกต์ Supabase จริง · การส่งอีเมลผ่านบริการ SMTP จริง · เรียลไทม์แบบไม่ล็อกอินบน Supabase จริง · การแสดงผลบนเบราว์เซอร์/มือถือจริง จึงควรทดลองตามข้อ 4–5 และลองจองจริงด้วยอุปกรณ์ 2 เครื่องก่อนเปิดใช้
